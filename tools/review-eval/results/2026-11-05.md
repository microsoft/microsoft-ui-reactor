# Reactor review-model pilot: 2026-11-05

## What this establishes

On one frozen Reactor PR snapshot, **GPT-6.1 Sol found more of the known runtime
defects at lower recorded cost among the complete reviews**. This is a
useful counterexample to choosing a review default by model reputation alone.
It is **not** a repository-wide ranking or a validated per-dimension routing
policy. There was one fresh trial per model, not repeated independent PR
samples; the Opus report did not complete all review dimensions.

None of the returned reports identified the five reference test-oracle gaps or
two documentation gaps. The incomplete Opus inspection is unmeasured coverage,
not a clean zero-finding review. Changing only the model does not establish
adequate coverage.

  (runtime fixes), then `1bcb4c6498bde619ad5f297611d803c809e91eff`
  (oracle/documentation fixes).
- Same source export, same combined seven-dimension rubric, `high` reasoning,
  default context tier, Copilot CLI **1.0.105**, and a **150-credit soft cap**
  per calibration run. The same setting name does not imply identical compute.
- Fresh CLI homes, no account memory or custom instructions, no Git history,
  review threads or later code, and only read/search tools. Every run's
  host-reported model and unchanged input hash were verified.
- Ten reference labels were frozen before inference. They were checked against
  historical source, review evidence and matching repairs; the historical
  WinUI reproductions/mutations were **not rerun locally**.
- Final reviews were masked before adjudication. The coordinator had seen run
  metadata, so this is not independent, fully blinded human adjudication.

## Comparable calibration results

| Model | Known runtime defects found | Known oracle/doc gaps found | Recorded AI credits | Elapsed |
|-------|----------------------------|-----------------------------|---------------------|---------|
| GPT-6.1 Sol | 2/3 | 0/7 | 43.76 | 3m 37s |
| GPT-6 Astra | 1/3 | 0/7 | 147.51 | 2m 36s |
| Claude Sonnet 5.5 | 0/3 | 0/7 | 43.67 | 3m 29s |
| Claude Opus 5.5 | Partial; excluded | Partial; excluded | 161.89 | 10m 06s |

Opus exceeded its soft cap on an in-flight response and reported incomplete
test/documentation inspection. It reported no reference hits, but that is not
a scored complete-review recall measurement. These are observations under this capped agent
workflow, not measurements of each model's maximum capability. Sonnet returned
human-readable dimension headings; they were normalized for quality scoring
without another model call, with strict schema compliance recorded separately.

The runtime labels were:

| Label | Defect | Detected by |
|-------|--------|-------------|
| R1 | A retained native dialog's `Opened` delegate retains the disposed reconciler/host | GPT-6.1 Sol, GPT-6 Astra |
| R2 | Reentrant disposal during content mount leaves later siblings' effects without cleanup | GPT-6.1 Sol |
| R3 | The live-update path can reattach replacement content after disposal | None |

The other labels cover the disposed-entry guard's missing oracle, a missing
throwing-window-host test, late-open and before-show assertions that can pass
for the wrong reason, deferred-fixture failure cleanup, missing disposal-contract
documentation, and the incorrect spec-section citation.

### Findings not in the reference set

An unmatched finding was **not automatically counted as false**.

| Model | Source-supported findings | Unsupported / outside the review contract | Unresolved |
|-------|---------------------------|------------------------------------------|------------|
| GPT-6.1 Sol | 2 | 0 | 0 |
| GPT-6 Astra | 1 | 0 | 0 |
| Claude Sonnet 5.5 | 0 | 2 editorial/debug-output notes | 3 |
| Claude Opus 5.5 | 0 | 1 side-table claim; 1 editorial note | 1 |

Both Claude reports raised a native-exception-during-retirement hypothesis.
Its conditional control flow is real, but a supported WinUI sequence that
triggers the exception was not established. It remains unresolved, not a
confirmed defect or a proven false positive.

Other useful adjudication evidence:

- The claim that `ShouldStartDeferredDialog` has no unit tests is contradicted
  by five tests in the frozen `FlyoutAttachmentTests.cs:482-518`. They are not
  in a file named `ContentDialog`. The broader multi-lifetime coverage suggestion
  remains unresolved.
- The pending-dialog CWT finding overlooks the explicit rare-association
  rationale at `OverlayLifecycle.cs:44-53` and the rooted anchor/lifetime
  invariant. Applying a general attached-state rule without that local exception
  produced an unsupported finding.
- Moving a correct paragraph to another heading, splitting unrelated work, or
  removing diagnostic output without a substantive defect did not satisfy the
  frozen high-signal review contract.

## Budget calibration and accounting

The initial design was four models, three adjacent snapshots, and two repeats,
with 30 credits per run. It was stopped after the first 12 scheduled reviews:
three usable reports and nine budget-censored/incomplete reports. An interrupted
13th startup has an empty event stream and no final usage export.

The 30-credit allowance was insufficient for a fair full-review comparison.
Those truncated results were **not** scored as zero-finding clean reviews and
were not mixed into the 150-credit comparison. Reprocessing them with the same
dimension-heading normalization did not change the three/nine split.

| Condition | Recorded review-run credits |
|-----------|-----------------------------|
| Initial 30-credit condition, 12 metered runs | 407.34001 |
| Approved 150-credit calibration, four runs | 396.83209 |
| **Recorded total** | **804.17210** |

The interrupted startup's final charge is unverified. These totals cover the
spawned review CLI runs, not the coordinating conversation or a settled billing
invoice. The approved ceiling was raised to 1,200 credits; CLI caps are soft,
not exact spending guarantees. No evaluation processes were left running.

## Implications, not promotions

1. Use GPT-6.1 Sol as the **next evaluation baseline**, not a declared universal
   winner. This case does not justify promoting Opus 5.5 to all deep reviews.
2. Test a focused test-oracle pass against the combined review at a matched
   budget. The lack of reference oracle hits in the returned reports is a
   workflow/rubric concern as well as a possible model concern; this pilot
   cannot separate the causes.
3. Check absence claims by symbol across the relevant test corpus, not only
   similarly named files. Account for documented local exceptions before
   enforcing broad architectural rules.
4. Calibrate a balanced block of **all** candidate models before expanding a
   matrix. Stop scheduling on incomplete reports, and pause gracefully so
   in-flight runs retain their usage exports.
5. Before changing routing defaults, use an untouched holdout such as
   [PR #1431](https://github.com/microsoft/microsoft-ui-reactor/pull/1431), repeat
   runs, and include fixed controls. Security/packaging and cross-family
   verification still need their own cases; neither was measured here.

There is no repeatability estimate, statistical superiority claim, or comparison
to the older model recommendations. This was one combined primary reviewer,
not the old seven-agent skill or the proposed model-routed workflow.
