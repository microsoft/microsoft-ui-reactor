Triaged the 29 inline comments from copilot-pull-request-reviewer and

Correctness fixes
- Trim-assertion forbidden list (TrimAssertionTests.cs): rename
  TreeViewHandler / TabViewHandler / FlipViewHandler / PivotHandler to
  the real *DescriptorHandler class names. The old strings would never
  match any symbol in the published binary, silently making the trim
  guard vacuous for those four descriptor-backed controls. Real
  correctness bug.
- Icon DSL overloads (Dsl.cs): replace the per-call
  ControlRegistry.RegisterDecorator with a one-shot IconRegistration
  latch. The singleton-handler decorator can't satisfy RegDecorator<>'s
  new() constraint, so we hand-roll the same closed-generic cctor
  pattern. Steady-state cost is now one indirect load, matching the
  Reg<>.Done cost model instead of allocating an adapterFactory closure
  and hitting ConcurrentDictionary.TryAdd on every Icon(...) call.

Registration timing — explicit static constructors
- Add explicit (empty) static constructors to Reg<>, RegDecorator<>,
  RegBase<>, RegBaseDecorator<>, ItemsRepeaterDescriptor.Registration,
  ItemsViewDescriptor.Registration, and the bench Reg<> shim. C#
  emits these types with the beforefieldinit flag otherwise, which
  lets the CLR run Init() at any point before the first Done read
  (including during JIT of an unrelated method). The explicit cctor
  binds initialization to precise before-first-use (ECMA-335 §I.8.9.5),
  matching the documented "first factory touch triggers registration"
  guarantee.
- Update XML comments / inline comments / bench csproj / phase2-baseline
  snippet to say "precise before-first-use" instead of "beforefieldinit".

Doc/comment accuracy fixes
