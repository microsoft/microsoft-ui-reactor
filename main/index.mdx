# Reactor

> Declarative UI framework for native Windows desktop apps in pure C#.

## Controls

- [Controls](https://microsoft.github.io/microsoft-ui-reactor/main/controls): Every visible thing on screen is a control. In Microsoft.UI.Reactor (Reactor) a control is the return value of a factory like TextBlock(...) or Button(...) — a plain element you compose, chain modifiers onto, and return from Render().
- [Forms and Input](https://microsoft.github.io/microsoft-ui-reactor/main/controls/forms): Every form control in Reactor follows the controlled-input pattern: you own the value, you provide the change handler, and the control reflects your state. There is no two-way binding. The data always flows one direction.
- [Collections](https://microsoft.github.io/microsoft-ui-reactor/main/controls/collections): When you need to render a list of data, Reactor provides three typed collection elements and a simple ForEach helper.
- [Text and Media](https://microsoft.github.io/microsoft-ui-reactor/main/controls/text-and-media): This page covers display text, inline rich text, rich-text editing, and media controls in Reactor.
- [Status and Info](https://microsoft.github.io/microsoft-ui-reactor/main/controls/status-and-info): Microsoft.UI.Reactor (Reactor)'s status and info controls report what the app is doing without stealing focus. Reach for them when the user needs to know something — a save succeeded, a long operation is running, a feature exists — and doesn't need to decide anything.
- [Dialogs and Flyouts](https://microsoft.github.io/microsoft-ui-reactor/main/controls/dialogs-and-flyouts): ContentDialog, MenuFlyout, CommandBarFlyout and Popup: when to reach for each one, and how to drive them from component state.
- [Data System](https://microsoft.github.io/microsoft-ui-reactor/main/controls/data-system): Reactor's data system provides a virtualized DataGrid<T> backed by a pluggable data source abstraction. You define columns (or auto-generate them), connect a data source, and the grid handles sorting, filtering, searching, selection, and inline editing.
- [Charting](https://microsoft.github.io/microsoft-ui-reactor/main/controls/charting): ReactorD3 brings data visualization to Microsoft.UI.Reactor (Reactor). The chart DSL provides high-level LineChart, BarChart, AreaChart, and PieChart factories that produce standard Reactor elements. You bind data, configure appearance with a fluent API, and the chart renders as native WinUI shapes on a Canvas.
- [Win2D canvas](https://microsoft.github.io/microsoft-ui-reactor/main/controls/win2d-canvas): Reactor.Advanced exposes the three Win2D canvas controls as Reactor elements. Add the package when you need immediate-mode drawing.

No XAML. No data binding. No view models. You describe your UI as a function of state, and Reactor keeps the screen in sync.

## Guides

### Core concepts

- [Components](https://microsoft.github.io/microsoft-ui-reactor/main/guides/components): Components are the building blocks of a Reactor app. Each component is a class with a Render() method that returns an element tree describing its UI.
- [Hooks](https://microsoft.github.io/microsoft-ui-reactor/main/guides/hooks): Hooks are functions you call inside Render() to manage state, side effects, and memoization. They replace the need for view models, event handlers, and lifecycle methods.
- [Effects and Lifecycle](https://microsoft.github.io/microsoft-ui-reactor/main/guides/effects): UseEffect runs side effects — code that reaches outside the component's render function. Timers, data fetching, subscriptions, and DOM manipulation all belong in effects, not in Render().
- [Context](https://microsoft.github.io/microsoft-ui-reactor/main/guides/context): Context lets you pass data through the component tree without threading it through every level of props. Define a Context<T>, provide a value at any level, and any descendant can read it with UseContext.
- [Commanding](https://microsoft.github.io/microsoft-ui-reactor/main/guides/commanding): A Command bundles an action with its metadata. Define it once and use it across buttons, menus, toolbars, and dialogs — the metadata stays consistent everywhere.
- [Advanced Patterns](https://microsoft.github.io/microsoft-ui-reactor/main/guides/advanced): Escape hatches for the few jobs the declarative model doesn't fit: error boundaries, memoized subtrees, element refs, direct property writes, view-model bridges, and custom hooks.

### Layout and styling

- [Layout](https://microsoft.github.io/microsoft-ui-reactor/main/guides/layout): Reactor provides a small set of layout primitives that compose to build any screen structure. Every layout element accepts children and optional spacing.
- [Flex Layout](https://microsoft.github.io/microsoft-ui-reactor/main/guides/flex-layout): FlexPanel is a Yoga-backed CSS Flexbox implementation, exposed through the FlexRow and FlexColumn factories. Reach for it when the layout needs alignment control, wrapping, or proportional sizing that VStack and HStack cannot express.
- [Styling and Theming](https://microsoft.github.io/microsoft-ui-reactor/main/guides/styling): Color and style your UI with theme tokens, named-style modifiers, and resource overrides that follow the Light, Dark, and high-contrast themes automatically.
- [Theming Tokens](https://microsoft.github.io/microsoft-ui-reactor/main/guides/theming-tokens): Reactor exposes 36 named theme tokens on the static Theme class plus a Theme.Ref(string) escape hatch for any XAML resource key.
- [Animation](https://microsoft.github.io/microsoft-ui-reactor/main/guides/animation): Reactor animations are declarative. You set the target value (opacity, scale, translation) and attach a transition modifier.
- [Input and gestures](https://microsoft.github.io/microsoft-ui-reactor/main/guides/input-and-gestures): Reactor's input surface is declarative: attach handlers via .On* modifiers and the reconciler wires WinUI events, auto-enables the matching flags (for example IsDoubleTapEnabled), and survives re-renders without re-subscribing the underlying WinUI event.

### Building apps

- [Navigation](https://microsoft.github.io/microsoft-ui-reactor/main/guides/navigation): Reactor uses a stack-based navigation model with type-safe routes. You define your routes as an enum, create a navigation handle with UseNavigation, and render the current page with NavigationHost.
- [Windows](https://microsoft.github.io/microsoft-ui-reactor/main/guides/windows): Most Microsoft.UI.Reactor (Reactor) apps start with the single window created by ReactorApp.Run. Larger desktop apps can open multiple native WinUI top-level windows with WindowSpec and ReactorApp.OpenWindow, while keeping the same declarative component model used inside a page.
- [Advanced Windowing](https://microsoft.github.io/microsoft-ui-reactor/main/guides/windowing-advanced): Some shell-window ideas are possible on Windows only by leaving the safe Reactor contract. We document the recipe so expert apps can make an informed choice, but Reactor does not ship these primitives as first-class WindowSpec fields.
- [Docking Windows](https://microsoft.github.io/microsoft-ui-reactor/main/guides/docking): Microsoft.UI.Reactor's docking system lets a single shell host multiple user-rearrangeable surfaces — the Visual Studio / VS Code / Photoshop / Figma layout idiom. Users drag tabs between groups, split panes, pin tool windows to a side, and tear panes out into floating sub-windows; layouts persist across sessions.
- [Async Resources](https://microsoft.github.io/microsoft-ui-reactor/main/guides/async-resources): Microsoft.UI.Reactor (Reactor)'s async hooks — UseResource, UseInfiniteResource, and UseMutation — replace the "one UseState for data, one for loading, one for error, one UseEffect to tie them together" pattern. They own the fetch lifecycle: cancellation on deps-change, drop late results after unmount, shared caching across siblings, and stale-while-revalidate by default.
- [Persistence](https://microsoft.github.io/microsoft-ui-reactor/main/guides/persistence): UsePersisted holds a value past a component re-mount — the user navigates away, the component unmounts, the user navigates back, and the captured state is still there.

### Ship your app

- [Accessibility](https://microsoft.github.io/microsoft-ui-reactor/main/guides/accessibility): Reactor provides accessibility modifiers on every component. They map directly to WinUI's automation properties, so screen readers, keyboard navigation, and test tools work out of the box.
- [Localization](https://microsoft.github.io/microsoft-ui-reactor/main/guides/localization): Microsoft.UI.Reactor (Reactor)'s localization system wraps your component tree in a LocaleProvider that supplies an IntlAccessor to every descendant via context. You look up messages, format numbers and dates, and detect RTL layouts — all locale-aware, all reactive.
- [Testing](https://microsoft.github.io/microsoft-ui-reactor/main/guides/testing): Microsoft.UI.Reactor (Reactor)'s render loop is deterministic and synchronous. A Component mounted in a unit test renders, runs effects, accepts state updates, re-renders, and disposes through the same code path the WinUI host uses — minus the WinUI tree at the bottom.
- [Performance](https://microsoft.github.io/microsoft-ui-reactor/main/guides/performance): A top-down performance workflow: take a trace with dotnet-trace or PerfView, learn what each span means, find the outlier, and reproduce a benchmark so a regression has a number behind it.
- [Packaging](https://microsoft.github.io/microsoft-ui-reactor/main/guides/packaging): A Microsoft.UI.Reactor (Reactor) app is a normal WinUI 3 / Windows App SDK executable — dotnet publish produces the deployable artifact and the framework itself adds nothing exotic to the project file.

### Developer tools

- [Dev Tooling](https://microsoft.github.io/microsoft-ui-reactor/main/guides/dev-tooling): Reactor's inner loop centers on dotnet watch and preview mode: you edit code, save, and see changes in a running window — no manual restart, no state-resetting class reload most of the time.
- [Visual Studio Embedded Preview](https://microsoft.github.io/microsoft-ui-reactor/main/guides/vs-extension): The Visual Studio Embedded Preview hosts a live Microsoft.UI.Reactor (Reactor) component inside a Visual Studio tool window — Visual Studio 2026 (18.x), with the Visual Studio extension development workload. Unlike the VS Code preview, which streams screenshots, the Visual Studio extension embeds the real WinUI surface so mouse, keyboard, focus, popups, and accessibility tree inspection work against the running app.
- [Diagnostics](https://microsoft.github.io/microsoft-ui-reactor/main/guides/diagnostics): This page is about reading Reactor's diagnostics from a real app — not about adding new events.

### Interop and migration

- [WinForms Interop](https://microsoft.github.io/microsoft-ui-reactor/main/guides/winforms-interop): Reactor components can run inside WinForms applications using XAML Islands. The Reactor.Interop.WinForms package provides XamlIslandControl — a standard WinForms control that hosts a Reactor component tree with full keyboard, accessibility, and theming support.
- [WPF Interop](https://microsoft.github.io/microsoft-ui-reactor/main/guides/wpf-interop): Host Reactor components inside a WPF app with a XAML island, until a first-class WPF host control ships.
- [Migration: Optional<T> controlled props](https://microsoft.github.io/microsoft-ui-reactor/main/guides/optional-t): Spec 050 changes controlled element-record properties from plain T to Optional<T>. Factory calls such as TextBox(text, setText), Slider(value, 0, 100, setValue), and ComboBox(items, index, setIndex) keep their existing plain-value signatures; they wrap the value in Optional<T>.Of(value) internally. Most app code therefore keeps compiling unchanged.
- [Migration: Windowing evolution](https://microsoft.github.io/microsoft-ui-reactor/main/guides/windowing-evolution): Spec 054 intentionally removes a few legacy windowing fields in favor of more explicit shapes. The new APIs are additive except for the breaking changes below.

## Recipes

- [Recipes](https://microsoft.github.io/microsoft-ui-reactor/main/recipes): A recipe is a small composition of Microsoft.UI.Reactor (Reactor) primitives that solves a real UI problem — login, master-detail, settings, paginated list, modal confirmation, multi-step form, search-with-suggestions, command palette, drag-to-reorder. The recipes here are not exhaustive apps; each is a single screen showing the pattern, and each ships a tiny doc app you can clone and adapt.
- [Recipe: Command Palette](https://microsoft.github.io/microsoft-ui-reactor/main/recipes/command-palette): A command palette is a filter-as-you-type list with a keyboard accelerator to open and Enter to execute. In Microsoft.UI.Reactor (Reactor) it's three UseState hooks, a static catalog of Command records, and an OnPreviewKeyDown handler — no menubar, no modal manager, no view model.
- [Recipe: Drag to Reorder](https://microsoft.github.io/microsoft-ui-reactor/main/recipes/drag-reorder): Drag-reorder is a UseState<List<T>> plus a function that splices one item from one index to another. Microsoft.UI.Reactor (Reactor)'s keyed reconciler does the rest — moves preserve identity, so the same row element keeps its focus, its hover state, and its place in the visual tree. Pointer drag is one entry point; an Alt+Up / Alt+Down keyboard shortcut is the second, and it carries the accessibility story.
- [Recipe: Login](https://microsoft.github.io/microsoft-ui-reactor/main/recipes/login): A Microsoft.UI.Reactor (Reactor) login form is four pieces working together: validated input, submit-gated state, an async call, and an error-display surface. The recipe below wires them with two UseState hooks and one UseMutation — no view model, no event handler classes, and no hand-rolled submitting / error flags.
- [Recipe: Master-detail](https://microsoft.github.io/microsoft-ui-reactor/main/recipes/master-detail): Master-detail in Microsoft.UI.Reactor (Reactor) is the canonical multi-pane shape: a list of records on one side, the selected record's details on the other. The whole thing is one UseState for the selected id and two slots in an HStack.
- [Recipe: Modal dialog](https://microsoft.github.io/microsoft-ui-reactor/main/recipes/modal-dialog): The modal is an element you return conditionally. There is no special "open dialog" API — when open is true the tree includes the modal panel layered over the page; when it's false the modal element is absent and the page renders alone.
- [Recipe: Multi-Step Form](https://microsoft.github.io/microsoft-ui-reactor/main/recipes/multi-step-form): A wizard form is a step-index UseState plus a switch on which step renders. The field state lives in the same component as the step index, so moving forward and back never loses what the user typed — Microsoft.UI.Reactor (Reactor) doesn't unmount the surrounding component when the visible slot changes.
- [Recipe: Paginated List](https://microsoft.github.io/microsoft-ui-reactor/main/recipes/paginated-list): A paginated list is four states sharing one source of truth: an initial load, a populated list, a "load the next page" affordance, and a terminal "no more results." UseInfiniteResource owns all four in Microsoft.UI.Reactor (Reactor) — the component below pattern-matches on LoadState and reads Items directly; there is no local UseState for loading or errors.
- [Recipe: Search with suggestions](https://microsoft.github.io/microsoft-ui-reactor/main/recipes/search-with-suggestions): The pattern is two slots: an input that owns the query string, and a dropdown that shows zero or more suggestions filtered against a catalog. UseMemo keys the filter on the query, so a re-render that didn't touch the query is free — important for the keyboard-up- arrow-down-arrow loop where the suggestion index changes but the query doesn't.
- [Recipe: Settings page](https://microsoft.github.io/microsoft-ui-reactor/main/recipes/settings-page): A settings page is many small persisted prefs side-by-side. Each preference is its own UsePersisted call with its own key — there's no central settings object that needs migration when one preference moves. The row layout is a single helper.

## Reference

### Hooks API

- [Hooks reference](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks): Hooks are how Reactor components subscribe to state, schedule effects, and reach into the framework's lifecycle from a function-shaped Render body. Each entry on this index is generated from the <summary> XML doc comments authored alongside the source in src/Reactor/Hooks/ — the canonical surface — and is grouped by the hooks category in docs/_pipeline/reference-map.yaml.

#### Hooks

- [UseAnnounce](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseAnnounce)
- [UseAnnounceExtensions](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseAnnounceExtensions): Extension methods for the UseAnnounce hook.
- [UseBreakpoint](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseBreakpoint)
- [UseCallback](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseCallback)
- [UseClosingGuard](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseClosingGuard): Registers a synchronous "can the window close right now?" predicate. Multiple guards stack — any returning false cancels the close. Runs on the UI thread; for async confirmation, return false and re-trigger ReactorWindow.Close from the dialog callback. No-op outside a window. (spec 036 §7 / §13.4)
- [UseCollection](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseCollection): Subscribes to an ObservableCollection and re-renders on Add/Remove/Reset. Returns the collection as IReadOnlyList.
- [UseColorScheme](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseColorScheme): Returns the app-global ColorScheme — ColorScheme.Light or ColorScheme.Dark, read from Application.Current.RequestedTheme.
- [UseCommand](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseCommand)
- [UseCommandState](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseCommandState): Allocates the stable hook shape shared by both UseCommand (guide) overloads: the IsExecuting / IsDebouncing state, the re-entrance guard and debounce-slot refs, and an unmount effect that disposes any live re-enable timer so it cannot fire setIsDebouncing / request a re-render against a torn-down context. These hooks are allocated unconditionally so the hook order is identical regardless of the command's shape.
- [UseContext](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseContext): Reads the nearest ancestor's provided value for the given context. Returns the context's DefaultValue if no provider exists in the ancestor chain. Follows hook rules — must be called in the same order every render.
- [UseDevtools](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseDevtools): Returns true when the current process is running with the in-app devtools UI enabled. This is the AND of two independent signals:
- [UseDisplays](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseDisplays): Returns the current display snapshot and re-renders when the display layout changes.
- [UseDpi](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseDpi): Returns the current per-window DPI (ReactorWindow.Dpi) and re-renders on DPI change. Returns the system primary-monitor DPI when called outside a window. (spec 036 §5.2)
- [UseEffect](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseEffect)
- [UseElementFocus](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseElementFocus)
- [UseElementFocusExtensions](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseElementFocusExtensions): Hook for imperative element focus (spec 027 Tier 5). Returns a stable ElementRef (survives re-renders) plus a RequestFocus action that schedules Input.FocusManager.Focus on the UI dispatcher. Scheduling defers focus past the current reconcile pass so callers can safely request focus from effects or event handlers without racing against layout.
- [UseElementRef](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseElementRef)
- [UseElementRefExtensions](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseElementRefExtensions): Hook that returns a strongly-typed ElementRef for binding to a concrete WinUI control via the .Ref(...) modifier. The typed ref removes the (Button)ref.Current cast at consumers (Composition, Ink, focus, …).
- [UseExternalStore](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseExternalStore): Subscribes to an external store that exposes a current snapshot getter. Re-renders only when a change notification yields a different snapshot.
- [UseFocus](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseFocus)
- [UseFocusExtensions](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseFocusExtensions): Extension methods for the UseFocus hook.
- [UseFocusTrap](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseFocusTrap)
- [UseFocusTrapExtensions](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseFocusTrapExtensions): Extension methods for the UseFocusTrap hook.
- [UseHighContrast](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseHighContrast): Returns true when the system is in a High Contrast (forced colors) theme. Automatically re-renders the component when high contrast is toggled.
- [UseHighContrastScheme](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseHighContrastScheme): Returns the high contrast scheme name (e.g., "High Contrast Black", "High Contrast White") or null if not in high contrast mode. Automatically re-renders the component when the scheme changes.
- [UseInfiniteResource](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseInfiniteResource)
- [UseInfiniteResourceExtensions](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseInfiniteResourceExtensions): Extension methods providing UseInfiniteResource on RenderContext.
- [UseIntl](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseIntl): Returns an IntlAccessor for the current locale. Re-renders this component when the locale changes via a parent LocaleProvider. If no LocaleProvider is present, returns a default accessor using the OS locale. Uses Context internally — the context system handles re-renders automatically.
- [UseIsActive](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseIsActive): Subscribes to the host window's activation events and re-renders on change. Returns true outside a window (the surface is "active" while shown). (spec 036 §7)
- [UseIsCovered](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseIsCovered): Returns a covered hint from the host window's z-order transitions and re-renders on change. The value is not pixel-accurate occlusion state.
- [UseIsDarkTheme](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseIsDarkTheme): Convenience wrapper — returns true when the app-global color scheme is ColorScheme.Dark. Exactly UseColorScheme() == ColorScheme.Dark, so it inherits that hook's semantics: it does not observe per-element RequestedTheme.
- [UseMemo](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseMemo)
- [UseMemoCells](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseMemoCells)
- [UseMemoCellsByIndex](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseMemoCellsByIndex)
- [UseMemoCellsByKey](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseMemoCellsByKey)
- [UseMemoCellsExtensions](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseMemoCellsExtensions): Cell-level memoization hook for high-frequency list / grid bodies. Reuses element references for cells whose item value (and declared dependencies) haven't changed since the previous render. The reconciler short-circuits on Object.ReferenceEquals, so reused cells skip diffing entirely.
- [UseMutation](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseMutation)
- [UseMutationExtensions](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseMutationExtensions): Extension methods providing UseMutation on RenderContext.
- [UseNavigation](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseNavigation)
- [UseNavigationLifecycle](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseNavigationLifecycle): Registers lifecycle callbacks that fire during navigation events.
- [UseObservable](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseObservable): Subscribes to an INotifyPropertyChanged source and re-renders when any property changes. Returns the same source object.
- [UseObservableProperty](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseObservableProperty): Subscribes to a specific property on an INotifyPropertyChanged source. Re-renders only when that property changes.
- [UseObservableTree](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseObservableTree): Observes an object and all nested INotifyPropertyChanged values reachable through its properties. Re-renders when any property at any depth changes. Automatically subscribes/unsubscribes as property values change.
- [UseOpenWindow](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseOpenWindow): Open or reuse a secondary window keyed by key. Renders that pass the same key share the same ReactorWindow; if the spec changes across renders the live window is updated via ReactorWindow.Update. The returned handle is identity-stable across renders so long as the key is stable.
- [UsePersisted](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UsePersisted)
- [UseReducedMotion](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseReducedMotion): Returns true when the user or system prefers reduced motion (e.g., Windows "Show animations" is off, or SPI_GETCLIENTAREAANIMATION returns false). Automatically re-renders the component when the preference changes.
- [UseReducer](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseReducer)
- [UseRef](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseRef): Returns a mutable ref object that persists across renders.
- [UseResource](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseResource)
- [UseResourceExtensions](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseResourceExtensions): Extension methods providing UseResource on RenderContext.
- [UseState](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseState): Declares a piece of state. Returns (currentValue, setter). Must be called in the same order every render (just like React hooks).
- [UseStateSetterByIndex](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseStateSetterByIndex): DEBUG ONLY: Directly set a UseState hook value by index and trigger re-render. Used for testing state changes without event handlers.
- [UseSystemBackButton](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseSystemBackButton): Subscribes to Alt+Left and VirtualKey.GoBack keyboard events on the given window's content to call NavigationHandle.GoBack. Unsubscribes on unmount.
- [UseTrayIcon](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseTrayIcon): Open (or reuse-by-TrayIconSpec.Key) a system-tray icon scoped to the calling component. The icon closes automatically on unmount — that's the only difference from ReactorApp.OpenTrayIcon, which is app-scoped and keeps the icon alive until explicit ReactorTrayIcon.Close.
- [UseWindow](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseWindow): Resolves the ReactorWindow whose host renders this component — including nested components and virtualized rows realized outside the host's render pass — or null when it has no owning window (tray-flyout content, ReactorHostControl embeds). O(1) field read; no subscription, no re-render trigger. (spec 036 §7 / §7.1)
- [UseWindowAspectRatio](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseWindowAspectRatio): Applies a lifetime-bound width/height aspect lock to the owning window. Last mounted hook wins; unmounting restores the previous writer.
- [UseWindowDragMove](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseWindowDragMove): Returns a stable callback that starts a framework-managed window drag/move loop (cursor polling + AppWindow.Move at ~60Hz until the left mouse button is released).
- [UseWindowPosition](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseWindowPosition): Subscribes to the host window's PositionChanged event and re-renders on change. Returns (0, 0) outside a window. (spec 054 §5.5)
- [UseWindowSize](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseWindowSize)
- [UseWindowState](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/UseWindowState): Subscribes to the host window's StateChanged event and re-renders on change. Returns WindowState.Normal outside a window. (spec 036 §7)

#### Types and options

- [Announce](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/Announce)
- [AnnounceHandle](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/AnnounceHandle): Handle returned by UseAnnounce (guide). Provides an imperative Announce (guide) method for screen reader live-region announcements plus a zero-size Region (guide) element that must be included somewhere in the component's rendered tree.
- [AnnounceRegionElement](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/AnnounceRegionElement): Internal Reactor element that mounts a hidden TextBlock with LiveSetting for announcements.
- [AnyLoading](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/AnyLoading): True iff any tracked token is currently Loading.
- [CacheKey](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/CacheKey): Overrides the generated cache key; null uses a key derived from deps. When set, the key identifies the query; deps changes alone do not cancel an in-flight request or start a new fetch. Include values that select different data in the key, for example $"user:{userId}".
- [CacheTime](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/CacheTime): Retention after the last subscriber leaves; null uses five minutes.
- [Changed](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/Changed): Fires when a resource joins, leaves, or changes its loading state.
- [Clear](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/Clear): Clears all registrations.
- [ComponentUseMemoCellsExtensions](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/ComponentUseMemoCellsExtensions): Component-class shims for UseMemoCellsExtensions (guide) so subclasses can call UseMemoCells without going through this.Context. Same semantics as the RenderContext extension methods.
- [Count](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/Count): Snapshot the number of registered tokens (loading or not). Diagnostic only.
- [CursorFromPageIndex](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/CursorFromPageIndex): Optional: computes the cursor for an arbitrary page index directly, bypassing the "wait for page N-1" constraint. Used by UseDataSource to expose the offset semantics of IDataSource's ContinuationToken, so deep scrolls fetch pages in parallel instead of walking the chain one round-trip at a time.
- [Customize](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/Customize): Author hook — add the bespoke descriptor entries for the [WrapManual] props.
- [Descriptor](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/Descriptor): The descriptor the engine interprets for every AnnounceRegionElement (guide).
- [Error](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/Error): Most recent error, or null if the last completion was a success or Reset (guide) was called.
- [Fields](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/Fields): Registered field names in order.
- [Focus](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/Focus)
- [FocusAttached](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/FocusAttached): Attached metadata for focus registration on elements.
- [FocusExtensions](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/FocusExtensions): Fluent extensions for attaching focus management to elements. Uses .Set() to capture the WinUI control reference during mount/update.
- [FocusField](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/FocusField): Focuses a specific field by name.
- [FocusFirst](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/FocusFirst): Focuses the first field from the given list that exists in this manager. Useful with ValidationContext.InvalidFields.
- [FocusManager](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/FocusManager): Manages focus for a set of registered form fields. Supports programmatic focus control, enter-to-advance, and field ordering.
- [FocusMeta](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/FocusMeta): Registers any element with a FocusManager via attached metadata (for custom types).
- [FocusNext](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/FocusNext): Focuses the field after the given field in registration order. If the current field is the last one, triggers submit.
- [FocusPrevious](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/FocusPrevious): Focuses the field before the given field in registration order.
- [FocusTrap](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/FocusTrap): Attaches a focus trap to this element. When the trap is active, Tab/Shift+Tab cycles within this element's visual subtree.
- [FocusTrapElementExtensions](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/FocusTrapElementExtensions): Fluent extension to attach a FocusTrapHandle to an element. The handle captures the mounted WinUI element for focus trapping.
- [FocusTrapHandle](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/FocusTrapHandle): Handle returned by UseFocusTrap. When active, traps keyboard focus within the container element so Tab/Shift+Tab cycles within the trapped scope. Essential for modal dialogs and flyouts.
- [GetFocus](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/GetFocus): Gets the FocusAttached metadata from an element.
- [IHookDispatcher](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/IHookDispatcher): Abstraction for marshalling continuations back to the render thread. Null-safe — if the callback is absent the continuation runs inline on the thread-pool completion thread (tests and headless hosts).
- [InfiniteHookState](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/InfiniteHookState): Per-hook state for UseInfiniteResource. Coordinates in-flight page fetches, cache subscriptions, deps-change restart, and unmount teardown.
- [IsActive](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/IsActive): Whether the focus trap is currently active.
- [IsFirstField](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/IsFirstField): Returns true if the given field is the first registered field.
- [IsLastField](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/IsLastField): Returns true if the given field is the last registered field.
- [IsPending](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/IsPending): True while at least one RunAsync (guide) call is in-flight.
- [LastResult](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/LastResult): Most recent successful result, or default if none yet.
- [Mutation](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/Mutation): Handle returned by the UseMutation hook. Carries the pending/error/last-result state and the RunAsync (guide) entry point.
- [MutationHookState](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/MutationHookState): Mutable state backing a single UseMutation hook instance. Owned per-component, per-hook-slot; disposed on unmount.
- [MutationOptions](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/MutationOptions): Callbacks and side-effects for the UseMutation hook. All callbacks are optional; all run on the dispatcher thread except OnOptimistic which runs synchronously on the caller of RunAsync (guide) — the typical case is a render-thread click handler, so the optimistic update lands in the very next frame without a dispatcher hop.
- [NotifyPending](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/NotifyPending): Called from RequestPage / page-completion paths to keep the Pending scope in sync.
- [Pending](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/Pending): Wraps child with a fresh PendingScope (guide). Renders fallback instead of child while any UseResource/UseInfiniteResource in the subtree is in the Loading state. Reloading(previous) does not trigger the fallback — spec §10.1.
- [PendingComponent](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/PendingComponent): Component backing the Pending element. Hosts a PendingScope (guide), subscribes to its Changed (guide) event, and chooses between Fallback and Child.
- [PendingFactory](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/PendingFactory): Entry-point factory for the Pending bubble-up element. See docs/specs/020-async-resources-design.md §10 for the full mechanism.
- [PendingProps](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/PendingProps): Props for PendingComponent (guide).
- [PendingScope](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/PendingScope): Shared loading-state ref-count consumed by the Pending element and populated by UseResource / UseInfiniteResource hooks inside the scope. When the scope observes any registered resource in the Loading state (not Reloading), the owning Pending element renders its fallback instead of the child subtree.
- [Post](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/Post): Enqueue action to run on the dispatcher thread.
- [RefetchOnMount](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/RefetchOnMount): Whether to fetch on a cache miss.
- [RefetchOnWindowFocus](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/RefetchOnWindowFocus): Whether to opt into window-focus revalidation.
- [Region](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/Region): A zero-size, invisible Reactor element that acts as the live-region anchor. Include this anywhere in your component tree (it renders nothing visible).
- [Register](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/Register)
- [Reset](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/Reset): Clear Error (guide) and LastResult (guide). Does not cancel or affect any in-flight RunAsync (guide) call.
- [ResourceHookState](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/ResourceHookState): Mutable state backing a single UseResource hook instance. Instances are owned per-component, per-hook-slot, and are disposed on unmount.
- [ResourceOptions](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/ResourceOptions): Tuning for the UseResource hook. Defaults mirror TanStack Query — zero StaleTime (guide) (always refetch-on-mount but dedup concurrent requests), five-minute CacheTime (guide).
- [RetryCount](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/RetryCount): Number of retries after a failed fetch.
- [RunAsync](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/RunAsync): Kick off the mutator with input. Returns a task that completes with the mutator's result or fault.
- [SetControl](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/SetControl): Associates a WinUI control with a field name. Called from .Set() during mount/update.
- [SetLoading](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/SetLoading): Update token's loading state. Silently ignored if the token was never registered (defensive — avoids forcing the caller to track whether they registered).
- [SetSubmitHandler](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/SetSubmitHandler): Sets the callback for submit (Enter on last field).
- [StaleTime](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/StaleTime): Freshness interval; null uses zero.
- [Unregister](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/Unregister): Stop tracking token. Idempotent.
- [WindowsDispatcherHookDispatcher](https://microsoft.github.io/microsoft-ui-reactor/main/reference/hooks/WindowsDispatcherHookDispatcher): Default IHookDispatcher (guide) backed by DispatcherQueue.GetForCurrentThread(). Falls back to inline invocation when called outside a WinUI dispatcher (unit tests).
