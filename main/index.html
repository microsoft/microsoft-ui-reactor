BlogMicrosoft.UI.Reactor: a C#-first way to build WinUI apps · Oct 21, 2026

Native Windows apps, in pure C#.

Reactor is a declarative UI framework for building native Windows apps with WinUI. Write your UI in C#, with no XAML, no data binding and no view models. Describe it as a function of state, and Reactor keeps the WinUI controls in sync.

Get startedComing from XAML

Built on WinUI, the Windows App SDK and .NET 10. Runs on Windows 10 and Windows 11.

class Counter : Component
{
    public override Element Render()
    {
        var (count, setCount) = UseState(0);

        return HStack(8,
            Button("- 1", () => setCount(count - 1)),
            TextBlock($"{count}").FontSize(20).SemiBold(),
            Button("+ 1", () => setCount(count + 1))
        ).Padding(24);
    }
}

  • Native WinUI

    Every element is a real WinUI control, with Fluent styling and accessibility built in. No web view, no Electron.

  • Pure C#

    No XAML, no data binding, no view models. Your UI is code you can step through.

  • Declarative

    Describe the UI for the current state. Reactor works out what changed.

  • Hooks for state

    UseState, UseEffect, UseReducer and more keep state next to the UI that uses it.

How it works

Reactor keeps a tree of plain C# records, compares it on every render, and patches only the WinUI controls that changed.

Start with architecture overview
  1. Render()

    Your component returns a tree of elements.

  3. Element tree

    Immutable C# records. Cheap to create and compare.

  5. Reconciler

    Diffs the new tree against the last one.

  7. WinUI controls

    Only the changed properties are set on real controls.
