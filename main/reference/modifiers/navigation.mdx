## `AutoRefreshDragRegions` [#autorefreshdragregions]

When `true`, the title bar re-derives its drag regions on every layout pass — the right fit for content that changes across renders. WinApp SDK ≥ 2.1.3. ## `FillContentArea` [#fillcontentarea]

Makes the tab content area fill the space the parent gives the TabView, instead of collapsing to the content's own height (issue #914).

```csharp
TabViewElement FillContentArea(this TabViewElement el, bool fill = true)
```

Declared in `ElementExtensions`.

**Applies to:** [`TabViewElement`](/microsoft-ui-reactor/main/reference/elements/navigation#tabviewelement).

**Parameters**

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `fill` | `bool` | `true` |  |

**Remarks**

WinUI's default TabView style sets `VerticalAlignment="Top"` on the control, so by default the tab body is sized to its content and a tab child with its own background paints only a band. An explicit `.VAlign(…)` on the TabView element always wins over this opt-in. See [`TabViewElement.FillContentArea`](/microsoft-ui-reactor/main/reference/elements/navigation#tabviewelement).

## `HeightOption` [#heightoption]

Sets the system caption height for the hosting window. (issue #917)

```csharp
TitleBarElement HeightOption(this TitleBarElement el, WindowTitleBarHeight height)
```

Declared in `ElementExtensions`.

**Applies to:** [`TitleBarElement`](/microsoft-ui-reactor/main/reference/elements/navigation#titlebarelement).

**Parameters**

| Name | Type | Description |
| --- | --- | --- |
| `height` | [`WindowTitleBarHeight`](/microsoft-ui-reactor/main/reference/hosting/window-options#windowtitlebarheight) |  |

**Remarks**

Applies both halves — the native caption (`AppWindow.TitleBar.PreferredHeightOption`) and, for [`WindowTitleBarHeight.Tall`](/microsoft-ui-reactor/main/reference/hosting/window-options#values_12), the control's own 48 DIP height, which the WinUI `TitleBar` control does not derive from the caption. An explicit `.Height(...)` on this element still wins. [`WindowSpec.TitleBarHeight`](/microsoft-ui-reactor/main/reference/hosting/WindowSpec#titlebarheight), when set, wins over this.

## `WithNavigation` [#withnavigation]

```csharp
TitleBarElement WithNavigation<TRoute>(this TitleBarElement el, NavigationHandle<TRoute> nav) where TRoute : notnull
NavigationViewElement WithNavigation<TRoute>(this NavigationViewElement el, NavigationHandle<TRoute> nav, Func<TRoute, string?> routeToTag, Func<string, TRoute> tagToRoute, Func<TRoute>? settingsRoute = null) where TRoute : notnull
```

Declared in `ElementExtensions`.

| Overload | Description |
| --- | --- |
| `WithNavigation<TRoute>(TitleBarElement, NavigationHandle<TRoute>)` | Auto-syncs this TitleBar's back button with a NavigationHandle: sets `IsBackButtonVisible` and `IsBackButtonEnabled` from `CanGoBack`, and wires `OnBackRequested` to `GoBack`. |
| `WithNavigation<TRoute>(NavigationViewElement, NavigationHandle<TRoute>, Func<TRoute, string?>, Func<string, TRoute>, Func<TRoute>?)` | Auto-syncs this NavigationView with a NavigationHandle: sets `SelectedTag` from the current route, navigates on selection change, wires `OnBackRequested` to `GoBack`, and `IsBackEnabled` to `CanGoBack`. NavigationView's recommended transition is forwarded to the navigation host, so pane navigation uses WinUI's entrance motion and top navigation slides horizontally according to the selected item's position.  Selection is wired through an internal transition-aware callback rather than the public [`NavigationViewElement.OnSelectedTagChanged`](/microsoft-ui-reactor/main/reference/elements/navigation#navigationviewelement), which this deliberately leaves null: setting that property yourself afterwards then takes precedence and suppresses the auto-navigation, so an author can observe selection without this fighting them. The same applies to [`NavigationViewElement.OnSettingsSelected`](/microsoft-ui-reactor/main/reference/elements/navigation#navigationviewelement).  The built-in settings item is opt-in: pass `settingsRoute` to make selecting it navigate. It is a separate parameter rather than a [`NavigationViewElement.SettingsTag`](/microsoft-ui-reactor/main/reference/elements/navigation#navigationviewelement) lookup through `tagToRoute` because that delegate must return a route for every string it is handed — callers typically throw on an unrecognized tag — so there is no way for it to decline. Left null, settings selection does not navigate.  To show the settings item as selected while its route is current, return [`NavigationViewElement.SettingsTag`](/microsoft-ui-reactor/main/reference/elements/navigation#navigationviewelement) from `routeToTag`. |

**Applies to:** [`TitleBarElement`](/microsoft-ui-reactor/main/reference/elements/navigation#titlebarelement), [`NavigationViewElement`](/microsoft-ui-reactor/main/reference/elements/navigation#navigationviewelement).

**Parameters**

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `nav` | [`NavigationHandle<TRoute>`](/microsoft-ui-reactor/main/reference/navigation/NavigationHandle) |  | The navigation handle obtained from `UseNavigation`. |
| `routeToTag` | `Func<TRoute, string?>` |  | Maps a route to its NavigationViewItem tag. Return null for routes without a corresponding menu item, or [`NavigationViewElement.SettingsTag`](/microsoft-ui-reactor/main/reference/elements/navigation#navigationviewelement) for the built-in settings item. |
| `tagToRoute` | `Func<string, TRoute>` |  | Maps a NavigationViewItem tag back to a route for `OnSelectedTagChanged`. Never called with [`NavigationViewElement.SettingsTag`](/microsoft-ui-reactor/main/reference/elements/navigation#navigationviewelement) — that value is reserved and routed via `settingsRoute` instead, so an ordinary item must not carry it or it will select without navigating. |
| `settingsRoute` | `Func<TRoute>?` | `null` | Route to navigate to when the built-in settings item is selected. Null (the default) leaves settings selection unrouted. |
