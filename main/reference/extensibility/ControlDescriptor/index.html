ControlDescriptor<TElement, TControl>

Spec 047 §6 / §14 Phase 2 (Q1 spike) — declarative control description.

A descriptor is the data-driven alternative to a hand-coded IElementHandler<TElement, TControl>. Authors declare property bindings (OneWay, ControlDescriptor.InitialOnly, ControlDescriptor.Controlled), an optional children strategy, and an optional factory; the interpreter (DescriptorHandler<TElement, TControl>) executes them against the same v1 protocol surface a hand-coded handler would use.

Phase 2 measurement gate (§13 Q1): the descriptor and the hand-coded handler shapes are evaluated head-to-head on the same M1 / M2 / M5 / M7 / M10 micro-benches and the L4 / L9 macros, then the §13 Q1 decision matrix determines which surface ships as the primary author path. See docs/specs/047-extensible-control-model.md §13 Q1.

Echo suppression (issue #206). A .Controlled / .HandCodedControlled entry suppresses the echo of its own programmatic write automatically — the interpreter wraps the write in the public ReactorBinding WriteSuppressed primitive (or arms a value-diff predicate when valueDiffEcho is set), so a framework-driven write never echoes back into the user’s OnChanged callback. Descriptor authors therefore never touch the suppressor directly; hand-coded IElementHandler<TElement, TControl> authors call WriteSuppressed themselves. See docs/guide/extending-reactor-controls.md.

Fluent author pattern:

public record ToggleSwitchElement(Optional<bool> IsOn = default) : Element;

public static readonly ControlDescriptor<ToggleSwitchElement, ToggleSwitch> Descriptor =
    new ControlDescriptor<ToggleSwitchElement, ToggleSwitch>()
        .OneWay(e => e.OnContent, (c, v) => c.OnContent = v)
        .OneWayConditional(e => e.Header, (c, v) => c.Header = v, e => e.Header is not null)
        .Controlled<bool, RoutedEventArgs>(
            get:          e => e.IsOn,
            set:          (c, v) => c.IsOn = v,
            subscribe:    (fe, h) => ((ToggleSwitch)fe).Toggled += (s, e) => h(s, e),
            unsubscribe:  (fe, h) => { /* trampoline lives for control lifetime */ },
            callback:     e => e.OnIsOnChanged,
            readBack:     c => c.IsOn);
public sealed class ControlDescriptor<TElement, TControl> where TElement : Element where TControl : FrameworkElement, new()

Namespace: Microsoft.UI.Reactor.Core.V1Protocol.Descriptor.

AfterChildrenMount

Spec 047 §14 Phase 3 prelude (Engine A1) — optional post-children mount hook. The interpreter (DescriptorHandler<TElement, TControl>) surfaces it through IElementHandler.AfterChildrenMount, which the adapter invokes after every child has mounted. Use for events that must subscribe after children-add (TabView SelectionChanged), or for imperative work that must run strictly after the prop loop AND the event subscriptions (FrameElement’s mount-time navigation, which would otherwise complete before its own Navigated/NavigationFailed handlers exist). Defaults to null (no hook). Set it from an object initializer, or — from a generated descriptor’s Customize hook, which receives an already-constructed descriptor — via ControlDescriptor.WithAfterChildrenMount.

OnUnmount

Optional teardown hook. The interpreter (DescriptorHandler<TElement, TControl>) surfaces it through IElementHandler.Unmount, which the engine invokes when the control leaves the tree. Use it to invalidate control-scoped state the descriptor created during mount and that the pool reset contract cannot see — a pending deferred write, a one-shot Loaded subscription, a disposable. Defaults to null (no hook). Set it from an object initializer, or — from a generated descriptor’s Customize hook, which receives an already-constructed descriptor — via ControlDescriptor.WithUnmount.

Not for event trampolines: those anchor to the control’s lifetime by design (see the unsubscribe no-op contract on ControlDescriptor.Controlled).

Declaring this hook makes DescriptorHandler<TElement, TControl> force the control’s ReactorState into existence at mount, because the engine’s unmount dispatch is tag-gated. That costs one small allocation per mounted control of this type, so declare it only when there is real teardown to do.

public DescriptorUnmountCallback<TControl>? OnUnmount  // get, init

HandCodedControlled

§14 Phase 3 (3.0.1) — escape-hatch builder for controlled (two-way) props on a control that needs a hand-authored trampoline against a user-supplied per-control event payload (TPayload). Required for multi-event controls (e.g. TextBox.Text alongside SelectionChanged) where the single-event fast-path DescriptorControlledPayload would collide if two controlled entries shared the same closed generic.

The payload type is typically reused from ControlEventPayloads.cs (e.g. TextBoxEventPayload) which already has a slot per event. slotIsNull + setSlot address the specific slot on the payload this entry owns; subscribe wires the user-supplied native TDelegate directly to the control’s event (no EventHandler<TArgs> bridge closure).

Mount/Update prop-write semantics are identical to ControlDescriptor.Controlled: unset skips writes, set values perform a bare initial write and a suppressed write on control drift. Subscription is gated on callback returning non-null on the mounted element.

valueDiffEcho replaces the Update write’s suppress-counter token with the spec 047 §8 value-diff arm, which the trampoline consumes on the next change event and which drops that event only when its readback matches the written value. armOnMount (requires valueDiffEcho) arms the Mount write too. Set it when the control raises its change event after the write returns (e.g. RichEditBox’s Document.SetText) and the trampoline cannot tell that echo apart on its own: the echo lands after the trampoline is wired and would otherwise reach the callback. The set lambda stays a plain write; the entry does the arming.

Imperative

§14 Phase 3 finish — Engine (4). Escape hatch entry that receives mount+(update with BOTH old and new TElement, so the entry can express a diff the per-value get/set lambdas of ControlDescriptor.OneWayConditional can’t: comparing one element field while writing a derived value elsewhere, or multi-source error context like Path.PathDataString’s path-markup converter/pre-built Geometry branches.

When to reach for it: only when the standard entries can’t express the diff or the write. Imperative entries skip the engine’s value-comparer fast-path, so a misused Imperative entry re-runs on every render. The other entry shapes (OneWay, ControlDescriptor.OneWayConditional, ControlDescriptor.CoercingOneWay, ControlDescriptor.HandCodedControlled) still cover the 95% case.

Distinct from Imperative<TElement, TControl> (a ChildrenStrategy<TElement, TControl> that drives the whole CHILD subtree imperatively) — this is a property-level escape hatch that participates in the normal prop loop.

public ControlDescriptor<TElement, TControl> Imperative(Action<TControl, TElement> mount, Action<TControl, TElement, TElement> update)

ImperativeBridged(Action<MountContext, TControl, TElement>, Action<UpdateContext, TControl, TElement, TElement>, Action<UnmountContext, TControl>)
